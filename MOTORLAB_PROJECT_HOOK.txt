PURPOSE
This file is the persistent project-side structural hook for MotorLab. When the project context is identifiable, MotorLab is implicitly and persistently enabled and loads the current canonical CORE from Br174/Chatgpt before write-capable or lifecycle-changing work.

MANDATORY RULES
1. Do not require Bruno to paste an activation string in each new GeoVision chat.
2. Every new identifiable GeoVision chat inherits MotorLab automatically by project context alone, even if the first message contains no software-build intent.
3. At the first available user-facing response of every recognized GeoVision chat/session, visibly state that MotorLab is active and operating alongside GeoVision's native engine.
4. If the visible MotorLab startup message has not appeared, Bruno must not be expected to assume that MotorLab is active.
5. After startup, apply current MotorLab progress percentage, watchdog lightning/recovery and verified fireworks-success contracts whenever applicable.
6. Br174/Chatgpt is authoritative; do not freeze a CORE copy here.
7. MotorLab must coexist with GeoVision native geospatial/POI/AI/runtime engines and must not replace, disable, absorb or rewrite them merely because MotorLab is active.
8. Before write-capable/lifecycle work, reconcile current CORE/governance/routing/registry and relevant durable job/checkpoint/lock state.
9. This hook is orchestration metadata only and must not alter application logic, UI, package identity, signing, Google-card/runtime behavior, map/POI logic, AI behavior or release behavior by itself.
10. MOTORLAB_GLOBAL_PERSISTENT_ACTIVATION_V1.txt is mandatory and remains inherited by this project until explicitly superseded by Bruno through canonical MotorLab governance.
11. If control state is unavailable, preserve project state and report the blocker rather than guessing.
12. Later canonical MotorLab governance revisions supersede frozen assumptions in this hook.
